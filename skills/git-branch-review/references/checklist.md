# Code Review 检查清单

审查代码变更时，按以下类别逐项检查。每个类别对应输出 CSV 中"问题类别"列的值。
检查项使用语言无关的通用表述，执行时根据项目实际语言对照具体语法和惯用法。
清单是保底项，不排除清单之外的问题——发现的非清单问题归入"其他"类别。

---

## 资源泄漏

> CSV 输出类别：`资源泄漏` | 基准严重程度：🟡 需关注

这类问题的特征是：获取了资源但未在所有代码路径上正确释放，长期运行后会导致资源耗尽。

- 数据库查询结果集（ResultSet / rows / cursor）是否正确关闭
- 文件句柄打开后是否正确关闭（finally / defer / try-with-resources / using）
- HTTP 响应体是否正确关闭
- 定时器、调度器是否正确停止
- 临时文件使用后是否清理
- 连接池、通道等资源是否正确归还或释放

## 并发安全

> CSV 输出类别：`并发安全` | 基准严重程度：🟡 需关注

这类问题的特征是：共享状态被并发访问时缺少同步保护，可能只在特定时序下才暴露。

- 共享可变状态是否有多线程/协程并发访问的锁保护
- 集合类型（map / HashMap / dict / Dictionary）在并发场景下是否线程安全
- 同步原语（锁、信号量、屏障）的获取和释放是否配对
- 异步任务 / 线程 / 协程是否存在泄漏（启动后无法退出）
- 单次初始化（Once / lazy init）是否正确实现

## 错误处理

> CSV 输出类别：`错误处理` | 基准严重程度：🟡 需关注

这类问题的特征是：错误被忽略、吞掉或不当处理，导致异常状态被掩盖或传播失真。

- 函数/方法的错误返回值是否被检查和处理（不能静默忽略）
- 异常/panic 是否有兜底保护（尤其在回调、事件处理器、后台任务中）
- 错误信息是否暴露了敏感内容（SQL 语句、内部路径、堆栈信息）
- 错误是否正确传播（wrap / cause chain / log，不能吞掉后无记录）

## 安全

> CSV 输出类别：`安全` | 基准严重程度：🔴 严重

安全类问题默认高严重程度，因为即使概率低，一旦被利用后果严重。

- 私钥、密码、token 等敏感内容是否提交到版本控制
- SQL 是否通过字符串拼接构造（参数化查询是否正确使用）
- 文件路径是否由外部输入直接拼接（路径穿越风险）
- TLS/SSL 配置是否正确（证书验证、协议版本、密码套件）
- 敏感信息是否出现在日志、错误消息或 API 响应中
- 用户输入是否做了校验和转义（XSS、命令注入等）

## 配置与硬编码

> CSV 输出类别：`配置与硬编码` | 基准严重程度：🟢 建议

这类问题通常不影响正确性，但会降低灵活性和可维护性。

- 应该可配置的值是否硬编码（端口、超时、密钥类型、目录路径等）
- 魔数是否应该提取为常量或配置项
- 环境变量 / 配置文件是否正确读取并生效
- 不同环境（dev / test / prod）的配置差异是否正确处理

## 数据一致性

> CSV 输出类别：`数据一致性` | 基准严重程度：🟡 需关注

这类问题的特征是：系统状态在部分失败或边界条件下出现不一致。

- 文件写入是否需要原子性（先写临时文件再 rename）
- 缓存与数据源的一致性（缓存失效策略是否合理，是否存在 stale data）
- 时间戳比较是否混用了不同来源（文件修改时间 vs 系统时钟）
- 多步操作是否需要事务保护（部分失败是否导致不一致状态）

## 死代码与可维护性

> CSV 输出类别：`死代码与可维护性` | 基准严重程度：🟢 建议

这类问题不影响运行时行为，但增加理解和维护成本。

- 是否有未被调用的函数、未使用的变量、未使用的导入
- 注释是否与代码逻辑一致（过时注释比没注释更危险）
- 函数/方法签名是否合理（参数过多、返回值含义不清）
- 命名是否清晰且一致（同一概念在代码中是否用同一个词）

## 性能

> CSV 输出类别：`性能` | 基准严重程度：🟢 建议

性能问题需要结合实际场景判断严重程度。在高频路径上的性能问题是 🟡，在低频路径上通常是 🟢。

- 循环内是否有不必要的重复计算或内存分配
- 是否有不必要的频繁磁盘 I/O 或网络调用（批量处理是否可行）
- 大对象是否在不再使用后仍被引用（内存泄漏）
- 查询是否有 N+1 问题（循环内逐条查询而非批量查询）

## 运行时与运维

> CSV 输出类别：`运行时与运维` | 基准严重程度：🟢 建议

这类问题关乎服务的可观测性和运维可控性，通常不直接影响功能正确性。

- 运行时参数（线程数、内存限制、GC 策略等）是否合理设置
- 健康检查接口是否正常工作
- 优雅停机逻辑是否完整（信号处理、资源释放、请求 drain）
- 日志级别是否合理（线上不应大量输出 Debug 级别日志）
- 关键操作是否有可追踪的日志（请求 ID、耗时、状态码）

## 其他

> CSV 输出类别：`其他` | 基准严重程度：视具体问题而定

以上类别之外的问题归入此类，按实际情况判定严重程度。

- 设计缺陷或不一致的架构决策
- 接口契约违反（调用方与实现方不匹配）
- 边界条件未处理（空集合、null/nil 指针、整数溢出）
- 测试覆盖缺失的关键路径
